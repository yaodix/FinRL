## 实盘 QMT 交易设计

## 当前阶段说明

本阶段只完成设计，不实现 QMT 交易代码。实盘接入必须在 Walk-Forward 验证、仿真推理验证和风控评审完成后再启动。

## 目标

为后续接入 QMT 提供最小可用的接口边界，保证训练研究代码和实盘执行代码解耦。

## 运行边界

1. 研究系统负责生成标准化信号。
2. QMT 网关负责账户查询、委托下单、委托回报、成交回报和持仓同步。
3. 风控网关位于信号与 QMT 之间，拥有最终拦截权。

## 推荐模块

1. signal_service：负责读取最新模型并生成信号
2. risk_gateway：负责校验信号是否合法、是否允许执行
3. qmt_gateway：负责和 QMT API 交互
4. account_sync：负责同步账户、持仓、资金和订单状态
5. execution_logger：负责记录指令、回报和异常

## 信号协议

统一信号结构建议至少包含：

1. timestamp
2. symbol
3. interval
4. action
5. target_position，MVP 可选
6. model_version
7. data_version
8. reason_code 或说明字段

## 执行流程

1. 新 Bar 完成后生成信号
2. 风控网关校验信号与账户状态
3. 转换为 QMT 可执行指令
4. 提交委托
5. 监听委托状态和成交回报
6. 回写订单和持仓状态
7. 推送结果到日志和监控系统

## 一致性要求

1. 研究环境中的 buy_all、sell_all、hold 必须能映射到实盘指令。
2. 实盘成交单位、费用和成交失败情况必须在回测中尽量模拟。
3. 若实盘侧无法保证下一 Bar 开盘精确成交，需记录执行偏差并在后续回测中修正假设。

## 故障处理

1. QMT 不可用时，系统进入只读监控模式，不下单。
2. 账户查询失败时，不允许盲目执行上一时刻信号。
3. 下单失败和部分成交必须记录，并同步更新持仓状态。

## 部署要求

1. 由于 QMT 通常运行于 Windows 环境，研究和训练环境可与实盘执行环境分离。
2. 建议训练研究在 Linux 完成，执行网关部署在可连接 QMT 的 Windows 主机。
3. 模型和信号发布采用文件或轻量服务方式同步，不直接耦合训练进程和 QMT 进程。
